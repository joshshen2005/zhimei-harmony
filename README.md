# 知美 AI 客服副驾

这是基于赛事 MOCK DATA 构建的可运行 Web 插件 MVP。它模拟千牛式三栏客服工作台，并在右侧提供消费者处境理解、跨源事实核验、回复草稿、风险跟进和案例沉淀。

## 已实现

- 导入998条聊天消息、113笔订单及五类共80张工单。
- 按会话 ID、订单号和工单号关联多源记录。
- 会话搜索、场景筛选、消息浏览和订单信息展示。
- 当前诉求、顾虑、明确偏好、情绪信号和未回应问题分析。
- S00018换货色号、S00072打款状态和聊天与工单时间差异检测。
- 带边界提示的行动建议与可编辑回复草稿。
- 风险事件创建、分派、处理、待核验和关闭状态流转。
- 相似会话检索、候选案例生成、人工审核和停止推荐。
- 浏览器本地持久化风险与案例操作。
- Node 内置测试覆盖三条核心演示链路及全部会话分析。

## 优化后的界面分层

- **接待队列**：集中提供风险数量概览、风险快捷筛选、关键词搜索、业务场景筛选和会话预览。
- **会话处理**：展示消费者、场景、订单、工单数量、聊天记录和人工回复框；顶部的“本次处理重点”同步提示风险、数据差异、漏答问题和待核验承诺。
- **AI 决策副驾**：按“理解—核验—行动—跟进”组织客服判断过程，并拆分为“当前处理”“跟进任务”“经验参考”三个工作区。
- **固定工作台**：页面锁定在浏览器视口内，左侧接待队列、中间聊天记录和右侧副驾内容分别独立滚动，互不带动。
- **当前处理**：依次呈现消费者处境、尚未回应的问题、跨源事实差异、下一步行动、不可承诺边界、可编辑回复草稿及证据来源。
- **跟进任务**：展示 AI 风险候选、人工确认的风险事件、负责人、下一步动作、状态流转和承诺履约清单。
- **经验参考**：检索同类历史会话，标注适用度和复用边界，并支持候选案例生成、人工审核和停止推荐。

## 客服实操流程

1. 在接待队列中优先查看高风险会话，也可按场景或关键词筛选；选择会话后，订单、聊天和副驾分析同步切换。
2. 先阅读“当前核心诉求”和“消费者处境”，确认诉求、偏好、顾虑、情绪信号及系统判断置信度。
3. 查看“尚未回应的问题”，避免只解决表面问题而漏掉消费者明确提问。
4. 在“核验业务事实”中比对聊天、订单与工单。出现差异时，点击“定位聊天证据”回到原始消息，不把待核验记录当作事实。
5. 按建议下一步处理，并检查“暂时不能承诺”，避免承诺尚未确认的库存、到账、出库或到货时间。
6. 审阅并修改 AI 回复草稿，点击“插入人工回复框”。草稿不会自动发送，必须由客服确认后再模拟发送。
7. 切换到“跟进任务”，人工确认 AI 风险候选并创建风险事件；按“已确认并分派—处理中—待核验—已关闭”推进，系统禁止跳过核验直接关闭。
8. 对聊天中的退款、补发、发货等承诺逐项核对履约证据，确保消费者获得明确结果而不是口头结案。
9. 处理完成后进入“经验参考”，查看相似历史会话。可生成候选案例，但只有人工审核通过后才进入可复用经验；发现案例失效时可停止推荐。
10. 返回接待队列继续处理下一会话；所有风险与案例操作在当前 MVP 中保存在浏览器本地。

## 重要边界

- 全部业务数据都是虚构 MOCK DATA。
- 图片消息只有路径，没有真实图片文件，因此不进行图片识别。
- 当前为离线复盘和交互演示，不读取真实库存、物流轨迹或支付流水。
- 模拟发送、任务分派和案例审核只写入浏览器本地存储。
- 不执行真实退款、赔付、补发或跨部门操作。
- 不对不良反应进行医疗诊断或治疗建议。
