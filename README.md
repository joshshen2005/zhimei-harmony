# 知美 AI 客服副驾

这是基于赛事 MOCK DATA 构建的可运行 Web 插件 MVP。它模拟千牛式三栏客服工作台，并在右侧提供消费者处境理解、跨源事实核验、回复草稿、风险跟进和案例沉淀。

在线演示：[Zhimei Harmony](https://joshshen2005.github.io/zhimei-harmony/)

公网 AI 后端：[zhimei-ai-backend.onrender.com](https://zhimei-ai-backend.onrender.com/api/health)

## 已实现

- 导入998条聊天消息、113笔订单及五类共80张工单。
- 按会话 ID、订单号和工单号关联多源记录。
- 会话搜索、场景筛选、消息浏览和订单信息展示。
- AI 归纳的核心诉求、关键顾虑、处理意向、情绪信号和未回应问题分析。
- GoEmotions 28 个可并存细标签、9 个客服策略组、VAD 1–5 量化、逐轮情绪轨迹与回复策略提示。
- S00018换货色号、S00072打款状态和聊天与工单时间差异检测。
- 带边界提示的行动建议与可编辑回复草稿。
- 风险事件创建、分派、处理、待核验和关闭状态流转。
- 独立“经验中枢”分屏：把历史会话结构化为带适用条件、处理动作、结果证据、不可照搬边界、规则版本与有效期的经验案例。
- 按当前场景、诉求关键词、风险等级、案例质量和处理结果计算适用度，只让已发布案例进入正式推荐。
- 支持经验库搜索与状态筛选、完整案例弹窗、有效/不适用反馈、引用至当前解决方案、候选案例生成、人工审核发布和停止推荐。
- 浏览器本地持久化风险与案例操作。
- 通过独立 Node.js 后端默认接入 DeepSeek Responses API，保留 OpenAI 切换能力，使用 JSON Schema 返回结构化分析。
- 模型服务不可用、超时或未配置时自动保留原有本地规则分析，不阻断客服操作。
- GitHub Pages 在线版本自动连接 Render 上的 DeepSeek 后端；密钥仅保存在 Render 加密环境变量中，不进入浏览器或 Git 仓库。
- 真实 AI 结果与确定性业务核验合并；AI 不能降低已由订单、工单和聊天证据确认的风险等级。
- Node 内置测试覆盖三条核心演示链路及全部会话分析。

## 启动

使用 Codex 工作区提供的 Python 运行时：

```bash
/Users/shenqingyang/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 scripts/build_data.py
/Users/shenqingyang/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 -m http.server 4173
```

浏览器访问：

```text
http://127.0.0.1:4173
```

不启动 AI 后端时，页面会正常使用本地规则。如需真实 DeepSeek 分析：

```bash
cd server
cp .env.example .env
npm install
npm start
```

在 `server/.env` 中配置 `DEEPSEEK_API_KEY`，然后回到页面点击右上角 AI 状态，测试并保存后端地址。不要在网页中填写 API Key。完整配置与 Render 部署方法见 [DeepSeek / OpenAI 接入与部署](docs/openai-integration.md)。

## 推荐演示顺序

1. 打开 `S00018`，查看消费者只接受 `#05枫叶红`，再查看换货工单记录的 `#01赤茶红` 冲突。
2. 将回复草稿插入人工输入框并修改，强调 AI 不自动发送。
3. 在单页“风险面板”中创建风险事件，依次更新到处理中、待核验和已关闭。
4. 进入“经验中枢”，查看推荐案例的适用度、匹配依据、处理结果和不可照搬边界；将适用经验加入当前解决方案。
5. 完成本次处理后生成候选案例，切换“待审核”筛选查看内容，人工审核后才会进入正式推荐。
6. 打开 `S00072`，展示到账反馈与打款工单待审核之间的冲突。
7. 打开 `S00012`，展示优惠券问题被漏答。

## 优化后的界面分层

- **接待队列**：集中提供风险数量概览、风险快捷筛选、关键词搜索、业务场景筛选和会话预览。
- **会话处理**：展示消费者、场景、订单、工单数量、聊天记录和人工回复框；顶部的“本次处理重点”同步提示风险、数据差异、漏答问题和待核验承诺。
- **AI 决策副驾**：右侧保持固定窄栏尺寸，上半区将“诉求与判断、业务核验、经验中枢、回复与闭环”拆成四个独立分屏，通过箭头和页码点单屏切换；左右箭头首尾循环，避免信息同时堆叠。
- **常驻 AI 对话**：插件下半区保留轻量对话框；询问产品、订单、物流、工单、风险、情绪或行动时，上半区会新增 AI 内容分屏并自动切换到该结果。
- **固定工作台**：页面锁定在浏览器视口内，左侧接待队列、中间聊天记录和右侧副驾内容分别独立滚动，互不带动。
- **情绪与策略**：显示当前客服策略组、多个细粒度情绪标签、VAD、置信度、逐轮变化和建议回应方式；完整 28 标签按需展开。
- **业务核验**：按时间线汇总聊天、订单、工单与客服承诺，冲突单独标红并可定位原始聊天证据。
- **风险面板**：展示风险分、等级、触发原因、建议负责人、响应时限、立即动作，以及人工事件的状态闭环。
- **处理与回复**：集中呈现建议行动、不可承诺边界、漏答提醒和通俗版回复草稿。
- **经验中枢**：默认推荐最适合当前会话的已发布案例，也可搜索全库并按已发布、待审核、已失效筛选；每条案例明确展示历史诉求、结果、适用条件、可借鉴动作、不可照搬边界、证据、规则版本与有效期。客服可反馈有效性、查看完整案例并引用至当前解决方案。

## 客服实操流程

1. 在接待队列中优先查看高风险会话，也可按场景或关键词筛选；选择会话后，订单、聊天和副驾分析同步切换。
2. 先读首屏总览：核心诉求是 AI 归纳，不是复制原话；同时确认下一步、客户希望的解决方式和服务边界。
3. 查看情绪策略组、细标签、VAD 与变化趋势，选择道歉、共情、解释、补问信息等回应方式。当前 MVP 明确标注为演示规则推断。
4. 沿业务时间线核对聊天、订单、工单和客服承诺。出现差异时，点击“定位聊天证据”回到原始消息，不把待核验记录当作事实。
5. 按建议下一步处理，并检查“暂时不能承诺”，避免承诺尚未确认的库存、到账、出库或到货时间。
6. 审阅并修改 AI 回复草稿，点击“插入人工回复框”。草稿不会自动发送，必须由客服确认后再模拟发送。
7. 在同一页风险面板确认触发原因、负责人和响应时限，再创建风险事件；按“已确认并分派—处理中—待核验—已关闭”推进，系统禁止跳过核验直接关闭。
8. 对聊天中的退款、补发、发货等承诺逐项核对履约证据，确保消费者获得明确结果而不是口头结案。
9. 进入“经验中枢”查看针对当前会话的案例推荐。先检查适用度与匹配原因，再打开完整案例核对适用条件、结果证据、规则版本、有效期以及不可照搬边界。
10. 将合适经验加入当前解决方案；系统只合并可借鉴的处理动作，不自动复制历史承诺。客服也可标记“有效”或“不适用”，为后续推荐留下反馈。
11. 回到“回复与闭环”，检查被引用的案例编号与新增动作，结合当前订单、规则和权限修改通俗版回复，再由人工发送。
12. 处理完成后点击“沉淀本次处理”，生成待审核候选案例；人工审核发布后才会进入正式推荐，失效案例则停止推荐但保留审计记录。
13. 返回接待队列继续处理下一会话；所有风险、反馈和案例操作在当前 MVP 中保存在浏览器本地。

## 重要边界

- 全部业务数据都是虚构 MOCK DATA。
- 图片消息只有路径，没有真实图片文件，因此不进行图片识别。
- 当前为离线复盘和交互演示，不读取真实库存、物流轨迹或支付流水。
- 未连接真实模型时，情绪概率是关键词规则产生的演示值；连接后的概率也是模型自评信心，未经校准，不能当作生产统计概率。
- 模拟发送、任务分派、经验反馈和案例审核只写入浏览器本地存储；当前静态演示尚不是多人共享的云端经验库。
- 不执行真实退款、赔付、补发或跨部门操作。
- 不对不良反应进行医疗诊断或治疗建议。
