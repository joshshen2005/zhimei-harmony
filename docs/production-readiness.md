# 知美 AI 客服副驾生产接入清单

当前版本是可以运行和演示的前端 MVP，但不能直接连接真实消费者或执行真实交易。投入生产前需要完成以下工作。

## 1 客服平台接入

需要提供：

- 当前客服平台名称、版本和技术接入方式。
- 会话列表、历史消息、实时新消息和消息发送接口。
- 订单、退款、物流、补发换货和售后工单查询接口。
- 工单创建、任务分派、状态更新和转接主管接口。
- 每个接口的认证方式、频率限制、超时规则和错误码。
- 测试环境、测试账号及最小权限凭证。

生产系统必须由后端代理这些接口，不能把密钥放在浏览器前端。

## 2 身份 权限与审批

需要明确：

- 客服、主管、质检、知识管理员和产品安全人员的角色权限。
- 哪些数据按品牌、店铺、渠道和岗位隔离。
- 哪些动作只允许建议，哪些动作允许人工确认后执行。
- 退款、补偿、补发、权益调整和产品安全事项的审批流程。
- 风险事件创建、转派、关闭和重新打开的权限。

前端隐藏按钮不能代替后端权限校验。

## 3 正式规则与知识库

需要提供：

- 当前有效的售后、物流、活动、赠品、会员和补偿规则。
- 每条规则的适用品牌、渠道、地区、时间和版本。
- 规则负责人、更新时间和失效条件。
- 不良反应和产品安全事件的标准操作流程。
- 升级主管、公关、法务或产品安全团队的触发条件。

历史客服话术不能自动作为正式规则。

## 4 数据与事件模型

至少需要稳定提供：

- `session_id`、`message_id`、`order_id`、`ticket_id` 和消费者主体标识。
- 业务事件的发生时间、写入时间、来源系统和版本。
- 订单、物流、支付和工单的状态历史，而不只是当前快照。
- 库存、出库、签收和支付流水等可核验事件。
- 消费者接受、拒绝、确认解决、重开和再次联系记录。

必须明确回放时点，防止 AI 使用当时尚未产生的未来数据。

## 5 AI 与 Agent 服务

需要决定：

- 最终使用的开源模型名称、版本、部署方式和许可。
- 模型运行在企业内网、专有云还是受控外部服务。
- 每个任务允许的工具、参数范围、调用次数、Token 和超时。
- 结构化输出 Schema、重试、降级和人工接管策略。
- 是否允许保存提示词、模型输入输出和调用日志。

生产 Agent 应只调用受控业务工具，不开放任意 SQL 或任意写入。

## 6 安全与合规

需要企业确认：

- 数据处理目的、范围、保存期限和删除机制。
- 敏感字段脱敏、日志最小化和附件访问控制。
- 数据是否允许进入模型、是否允许用于训练或评测。
- 跨品牌、跨店铺和跨地区的数据隔离要求。
- 提示注入、越权调用、数据外泄和异常访问的防护方案。
- 审计日志、告警、应急响应和人工追责机制。

## 7 生产后端

建议至少建设以下服务：

- API 网关和企业身份认证。
- 会话、订单、工单和规则查询服务。
- Agent 协调器和受控工具层。
- 风险事件与承诺任务状态机。
- 案例审核与检索服务。
- 操作日志、模型日志和审计日志。
- 数据同步、索引更新、缓存失效和失败补偿。

数据库需要保留来源、版本和状态历史，不能只保存模型生成的摘要。

## 8 测试与上线门槛

上线前至少需要：

- 按会话和近重复模板分组的独立测试集。
- 数据关联、事实支持、诉求识别、漏答检测和冲突检测评测。
- 建议可执行性、越权建议和无依据承诺评测。
- 高风险产品安全场景专项审核。
- 并发切换会话、新消息到达、人工编辑保护和接口失败测试。
- P50 与 P95 时延、Token、调用次数、失败率和成本报告。
- 影子运行、少量人工确认试点、分阶段放量和回滚方案。

## 9 建议实施顺序

1. 确定首期品牌、渠道和三类服务场景。
2. 获取测试环境接口和权限矩阵。
3. 建立只读查询后端，先实现事实卡和跨源核验。
4. 接入规则库和受控 Agent，保留人工回复确认。
5. 建立风险状态机和审计日志，再开放任务写入。
6. 建立案例候选、人工审核和版本失效机制。
7. 影子运行并完成独立评测。
8. 在低风险场景小范围上线，再逐步扩展。

## 10 你们下一步需要提供的材料

为了把当前 MVP 继续改造成可连接真实平台的版本，请提供：

1. 客服平台名称和 API 或 SDK 文档。
2. 测试环境接口地址及脱敏测试凭证。
3. 角色权限矩阵和审批流程。
4. 正式业务规则与版本管理方式。
5. 期望使用的模型和部署环境。
6. 目标部署方式，例如企业内网服务器、容器平台或专有云。
7. 安全与合规团队提出的数据边界。
8. 首期要真正上线的品牌、渠道和业务场景。
